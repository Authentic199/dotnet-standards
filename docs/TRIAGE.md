> Never default to `skip` (rules §4). Each row is compared against the equivalent Superpowers
> capability and assigned `skip` / `keep` / `combine`.
> **R5 — every `keep` and `combine` MUST answer all five conflict-check items** in the row:

**Windows cost, measured rather than assumed.** Superpowers' own `hooks/run-hook.cmd` is a
working reference implementation of the polyglot wrapper, and reading it established two facts
`02-repo-structure.md` did not: (a) hook scripts must be **extensionless** (`session-start`, not

`.sh` — so keeping a kit hook means **renaming the script as well as shipping the wrapper**, and
the kit's own `bash "${CLAUDE_PLUGIN_ROOT}/hooks/x.sh"` command form is unusable as written;
(b) when no bash is found the wrapper **exits 0 silently**, so the hook simply never runs and
nothing reports it. Fact (b) is the decision rule for the whole of B.3: a hook whose absence is
**benign** may pay the cost, a hook whose absence **fails open** may not.

distinction that kept A13 in Group A and sent A08's anti-pattern blocks to the log.

> Resolves open questions **Q2** (format-hook viability) and **Q4** (the deferred
> `UserPromptSubmit` skill-index hook, mechanism E — a *new* component, not a kit row).
> Every `keep`/`combine` row must state the `run-hook.cmd` Windows cost in its Reason.
>
> **Only three of the seven scripts are Claude Code hooks at all** — `hooks.json` registers
> `pre-bash-guard`, `post-edit-format` and `post-scaffold-restore`, and nothing else. The kit's own
> README states the three-kinds taxonomy explicitly: **Claude Code hooks** declared in `hooks.json`
> · **git pre-commit hooks** installed by hand · **utility scripts** invoked by a workflow. That
> taxonomy makes R5 item 1 *inert by construction* for B26, B28, B29 and B30 — they register no
> event — and inert *by measurement* for B24, B25 and B27, since Superpowers occupies only
> `SessionStart`. **There is no hook-event collision anywhere in Group B.**

> failure mode, not the effort. The wrapper is a fixed one-time cost; the variable cost is one
> rename per script. What differs is what happens when Git for Windows is absent and
> `run-hook.cmd` exits 0 in silence: a **benign** absence (formatting does not run, and a later
> check catches the drift) may pay the cost; a **fail-open** absence (a guard silently stops
> guarding, with no signal, while the user believes it is running) may not. That asymmetry is the
> substance of **Q2**.
